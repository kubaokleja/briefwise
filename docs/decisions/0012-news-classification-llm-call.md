# 0012. News classification LLM call: structured output, model, few-shot, effort, caching, retries

- Status: Accepted
- Date: 2026-10-24

## Context

M1 slice 4 adds the first LLM adapter: one news item in, one `NewsClassification` out
([DESIGN 7.1](../DESIGN.md#71-news-pipeline-m1)). The convention is structured output into a record, every call in
`ai_generation_log`, budget checked before and recorded after, and invalid structure -> retry -> fallback
([DESIGN 12.1](../DESIGN.md#121-engineering-conventions)). Starting proposals are in
[DESIGN 8](../DESIGN.md#8-ai-and-engineering-decision-points) and [13.4](../DESIGN.md#134-cheap-model-cached-prefix-batches).

Facts checked 2026-10-24 in the Spring AI 2.0.2 sources and the Claude docs:
- Spring AI 2.0.2 (latest GA; 2.1.0 is RC) builds its Anthropic model on the official `anthropic-java` SDK 2.72.0.
  The SDK retries transport errors itself (`spring.ai.anthropic.max-retries`, default 2) with a request timeout
  (`spring.ai.anthropic.timeout`, default 60 s).
- `ChatClient` can ask the provider to enforce a JSON schema ("native structured output"): the schema generated by
  `BeanOutputConverter` goes into Anthropic's `output_config.format`. Providers that cannot do this get the schema
  as text instructions instead. `validateSchema()` re-asks the model inside one call, so those extra calls would
  not reach our generation log.
- Claude Haiku 5.5 supports structured outputs, but enum casing is not guaranteed. The first call with a new schema
  waits for grammar compilation, and compiled grammars are cached for 24 h.
- Haiku 5.5: "Omit `temperature`, `top_p`, and `top_k`". It uses adaptive thinking (default effort `medium`), and
  thinking tokens count toward `max_tokens`. DESIGN's "temperature 0" no longer applies to this model.
- Prompt caching: 512-token minimum prefix for Haiku 5.5, otherwise it is silently not cached. TTL 5 min (write
  1.25x input price) or 1 h (2x). Read 0.1x.

## Options

**L1 structured output**
1. Prompt-based `BeanOutputConverter`: schema as text in the prompt, parse the reply. Works with any model, but
   malformed JSON is possible.
2. Native structured output with the same converter's schema: the API constrains decoding, so malformed JSON can
   only come from truncation or a refusal. Ollama support is model-specific.
3. Forced tool call: the older workaround for the same effect; more code, no benefit now.

**L2 model**: Haiku 5.5 (cheapest, built for classification) vs Sonnet 5.5 (20x the price). For dev with Ollama:
`llama3.1:8b` (Spring AI docs suggest it for structured output) vs Qwen3 (reasoning text breaks JSON parsing).

**L3 few-shot**: none; 3-5 static examples; examples selected by similarity per item (needs embeddings, M2).

**L4 sampling**: `effort` low vs default `medium` (temperature is not available). `maxTokens` must leave room for
thinking.

**L5 caching**: cache the system prompt now (5 min TTL), or leave it off until the slice 8 batch eval.

**R1 resilience** beyond [ADR 0005](0005-resilience-spring-retryable.md): keep it (timeout + bounded retries, no
circuit breaker) or add a Resilience4j circuit breaker now.

## Decision

- **L1: option 2.** The adapter generates the schema with `BeanOutputConverter`, passes it as native structured
  output through the `ChatClient` context, takes the raw `ChatResponse`, and parses it itself. Each attempt,
  including a malformed one, is logged and budgeted. No `validateSchema()`. Enums are parsed case-insensitively.
  A parse failure or an invalid value (e.g. a ticker the item does not have) gets **one** re-ask. If that also
  fails, the item becomes `UNCLASSIFIED` (fallback, logged with `is_fallback`).
- **L2:** `claude-haiku-5-5` for `anthropic`; `llama3.1:8b` for `ollama`. Names in `application.yml` only. The
  final model choice comes from the slice 8 eval.
- **L3:** 4 static examples inside the system prompt (an `<examples>` block), so the cached prefix covers them:
  `SYSTEM_ONLY` caching does not reach user/assistant message pairs, and native structured output already enforces
  the format that message pairs would demonstrate. They are **synthetic** headlines written to mirror the
  few-shot pool's label patterns, not real rows: the pool is Finnhub data (licence: no redistribution) and
  `prompts/` is committed. Never from the golden set.
- **L4:** effort `low`, `maxTokens` 1024 (JSON output is about 100 tokens; the rest is headroom for thinking).
  Temperature unset for Anthropic, 0 for Ollama.
- **L5:** cache strategy `SYSTEM_ONLY`, 5 min TTL (a daily run classifies all items within minutes). V11 adds
  cache-write and cache-read token counts to `ai_generation_log`. Cost uses per-model cache prices (default 1.25x
  / 0.1x input). The prefix is checked against the 512-token minimum in a test.
- **R1: keep ADR 0005, no circuit breaker.** SDK timeout 20 s, `max-retries` 1 (two transport attempts). The
  one re-ask is only for invalid structure; a provider error after the SDK's retries ends the item at once. Classification failures never throw to the Kafka listener, so its retries do
  not multiply calls. A budget-exhausted gate leaves the item `RECEIVED` for the sweep (slice 6).
- `PROMPT_VERSION` lives in `prompts/news-classification/prompt.properties` with a SHA-256 of the prompt files; a
  unit test fails when the prompt changes without a version bump.

## Consequences

- Haiku cost per item is about 700-900 input + ~100-300 output tokens. At 100 items/day that is well below 1 cent;
  caching saves fractions of a cent, so it is kept mainly to learn and verify `cache_read_input_tokens`.
- Synthetic few-shot examples may teach slightly different patterns than real headlines; slice 8 measures with and
  without them.
- Up to 2 HTTP attempts x 20 s per item if the provider is down; the job's `max-duration` (slice 6) bounds a
  whole run. Revisit with a circuit breaker if runs time out in practice.
- Thinking cannot be fully turned off from config here; if latency or cost shows it matters, test
  `thinking: disabled` support for Haiku 5.5 via the Models API.
- Supersedes nothing; DESIGN 7.1 and 8 now say that Haiku 5.5 uses effort instead of temperature 0.
